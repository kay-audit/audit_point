# Redis на DEV-машине: как это устроено и что делать руками

> Как поднять Redis для DEV на Windows (через WSL) и что делать, если он не
> отвечает. Redis — обязательная инфраструктура приложения: ОТП-коды и сессии,
> кэши (роли, user-контекст, счётчик уведомлений), блокировки актов и транспорт
> LLM-моста (маршруты `redis-bridge,*` — см.
> [`docs/integrations/redis-llm-bridge.md`](../integrations/redis-llm-bridge.md)).
> Без него приложение не стартует, причём независимо от `AUTH__ENABLED`: init
> идёт безусловным хуком старта (`app/core/redis.py`, `init_redis`). Это
> сделано специально — лучше упасть сразу с понятной ошибкой, чем работать
> наполовину.

## Как это устроено (три матрёшки)

1. **WSL** — «мини-Linux внутри Windows». В нём стоит дистрибутив Ubuntu-24.04.
2. **redis-server 7.0.15** — установлен внутри этой Ubuntu как системная служба:
   когда Ubuntu поднимается, Redis стартует сам.
3. **Якорь** — маленький скрипт в автозагрузке Windows. Нужен из-за особенности WSL:
   Windows «глушит» мини-Linux примерно через минуту после того, как с ним перестали
   общаться — вместе с Redis. Якорь просто держит с ним связь вечно.

Аналогия: Ubuntu — это подсобка, Redis — холодильник в ней, а якорь — нога в дверном
проёме, чтобы дверь подсобки не захлопнулась (Windows любит её закрывать).

**После перезагрузки компьютера ничего делать не нужно** — при входе в Windows
автозагрузка запускает якорь, тот будит Ubuntu, Ubuntu поднимает Redis. Секунд через
10–15 после логина всё живо.

## Проверить, что Redis жив

Самый честный способ — спросить его самого (из PowerShell или любой консоли):

```powershell
python -c "import socket; s = socket.create_connection(('127.0.0.1', 6379), timeout=3); s.sendall(b'PING\r\n'); print(s.recv(20)); s.close()"
```

Ответ `b'+PONG\r\n'` = всё работает. Если «отверг запрос на подключение» — см. ниже.

Посмотреть состояние службы изнутри:

```powershell
wsl -d Ubuntu-24.04 -u root -- systemctl status redis-server
```

## Запустить руками (если не поднялось)

По одной команде за шаг — каждая безвредна, если всё уже работает:

```powershell
# 1. Разбудить Ubuntu и запустить службу Redis
wsl -d Ubuntu-24.04 -u root -- systemctl start redis-server

# 2. Поставить «ногу в дверь», чтобы Windows не заглушил Ubuntu через минуту
#    (окно можно свернуть, но не закрывать; либо просто перелогиниться —
#    автозагрузка сделает то же самое незаметно)
wsl -d Ubuntu-24.04 --exec sleep infinity
```

Перезапустить Redis (например, после правки его конфига):

```powershell
wsl -d Ubuntu-24.04 -u root -- systemctl restart redis-server
```

Остановить всё разом (Redis умрёт вместе с Ubuntu):

```powershell
wsl --shutdown
```

## Если PING не отвечает — по порядку

1. **Проверь, жива ли Ubuntu:** `wsl -l -v`. Если `Stopped` — якорь не отработал;
   запусти два шага из раздела «Запустить руками».
2. **Подключаешься по `localhost`?** Так не работает — только `127.0.0.1`.
   Windows превращает «localhost» в IPv6-адрес, а туда Redis не проброшен.
   В `.env` уже правильно (`REDIS__HOST=127.0.0.1`) — не менять на localhost.
3. **Свежая перезагрузка?** Подожди 15 секунд после входа в Windows и повтори PING.
4. **Логи Redis:** `wsl -d Ubuntu-24.04 -u root -- journalctl -u redis-server -n 30`.

## Что где лежит (если захочется покрутить)

| Что | Где | Зачем |
|---|---|---|
| Автозагрузка якоря | `Win+R` → `shell:startup` → `wsl-redis-autostart.vbs` | Удалить файл = отключить автостарт |
| Сетевой режим WSL | `C:\Users\mr-de\.wslconfig` | Режим mirrored — благодаря ему Windows видит Redis. Удалить + `wsl --shutdown` = вернуть как было |
| Конфиг Redis | внутри Ubuntu: `/etc/redis/redis.conf` | Правили одну строку: `bind 0.0.0.0 -::1` (иначе из Windows не видно). Защита от чужих включена (`protected-mode yes`) |
| Настройки приложения | `.env`, блок `REDIS__*` | Хост/порт/пароль/номер БД. DEV (`.env.dev`): `127.0.0.1:6379`, `REDIS__DB=0`. ПРОМ (`.env.prod`): `10.110.10.38:7474` |

## Redis и тесты

- **pytest** живого Redis не требует: глобальная autouse-фикстура в
  `tests/conftest.py` подставляет `fakeredis` в модульный синглтон адаптера
  (свежий инстанс на каждый тест, Lua-скрипты исполняет `lupa`).
- **Playwright (E2E)** требует **настоящий** Redis. `tests/playwright/global-setup.ts`
  делает `PING`, переключается на **db 15** и чистит её (`FLUSHDB`) — рабочая
  `db 0` не затрагивается. Если Redis не отвечает, прогон падает сразу с
  подсказкой на этот файл, а не «странными» ошибками в браузере.

## Почему WSL, а не «родной» Windows-Redis

Требование: один и тот же код на DEV (Windows) и ПРОМ (Linux). В WSL крутится
**точно такой же linux redis-server, как на ПРОМе** — приложение разницы не видит
вообще, меняются только две строчки адреса в `.env`.
